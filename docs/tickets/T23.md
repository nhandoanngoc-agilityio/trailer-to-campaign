# T23: Slack Runs read a local copy of the public trailer

[#61](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/61) · PR [#62](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/62) merged, review fixes in a follow-up PR

A Film can name a local copy of its public trailer, so a Run doesn't depend on YouTube or Vimeo answering on the day of a trial or a demo.

## Spec

A Slack Run took its trailer only from a link, and every Run asked the video site for that link's details. On 2026-11-03 YouTube refused this machine with a bot check, then stopped refusing it within the hour. Vimeo refused a public video with a login message and was still refusing when this was written.

- **Done when:**
  - Mentioning a Film that has `trailer_file` starts a Run on that file, and the downloader is never called.
  - `t2c run --film <film>` uses the same default, and `--source` still overrides it.
  - A message link that differs from the catalog's `trailer` still wins. The catalog's own link, with or without the slug, uses `trailer_file`.
  - `film.toml` is refused when `trailer_file` has no `trailer` link beside it, holds a path, or looks like a screener.
  - A missing file gets a refusal in Slack that names no local path, and no Run starts.
  - A file outside `source/` can't be reached, by name, by `../` or by a symlink.
  - Films without `trailer_file` behave as before, including Eval Set Runs.
  - `films/README.md` and `docs/side-by-side.md` say how to use it, and that the file must be the same cut as the public trailer.
- **Decisions:**
  - The public `trailer` link stays required beside `trailer_file`, because slice 1 takes public trailers only (ADR 0005).
  - The order is: a different link in the message, then `trailer_file`, then the catalog's link. `--source` overrides all of them.
  - No new glossary term: this is a field, not a domain word.

## Plan

The plan was approved before Build. Tests came first, then `catalog.py`, `slack_request.py` and `cli.py`, then the docs. `footage/sources.py` changed only in the review fixes, which moved its local checks into `local_trailer` so a Run's pre-flight shares them.

**Changed during Build:** `trailer_file` sits on `Film`, not `Catalog`. The plan was to drop it from `get_catalog`, but `pipeline.py` also dumps `Catalog` for tracing, so keeping it off `Catalog` covers both, and `tools/catalog.py` didn't need to change.

**Added during Build:** the file name must fully match a plain-name pattern, because the name reaches the Watcher's task prompt. The review fixes made it stricter: no spaces, and at most 120 characters.

**Added after the live check:** the plan said the Run Log's footage id would show which file a Run read, but the Run Log had no footage id. The Watcher now logs a `footage_read` event with the trailer and its footage id, on both harnesses. It's Run Log only: nothing changes in a prompt or in what a model sees.

## Tests

The suite went from 945 to 985 tests, counting the review fixes. The new ones prove:

- which trailer wins, in Slack and on the CLI
- each refused `trailer_file`: no link, a path, `..`, a hidden name, a URL, a screener name, a line break, a sentence, an over-long name
- a missing, over-size or symlinked file stops before any Run, or an unreadable folder does, and the refusal names no local path
- the footage tool reads the file with a downloader that fails if called
- `--source` overrides the default for both `t2c run` and `t2c watch`
- `get_catalog` leaves the file name out, and Eval Set Films keep their links
- the Run Log records which trailer the Watcher read, with its footage id, and one it failed to read

## Evidence

- `uv run pytest`, with the review fixes: 985 passed, 1 deselected. `ruff check` and `ruff format --check` pass.
- The real footage tool on a gitignored check Film, `t23-check`, with `trailer_file` set: 88 frames and a 231.5 s duration, and `footage_id` `c8e7a23038c3` matches the first 12 hex of the file's sha256. No model was called.
- **Not shown:** that check doesn't prove a Run survives a block, because YouTube had stopped refusing by then and the link route also downloaded. The test with the failing downloader proves the local route makes no download call.
- **Live in Slack:** a mention of `t23-check` reached Key Moment Approval (Run `runs/t23-check/20261103T085427Z`, $0.23). The human stopped the app there, so the Run ended with `stop_reason: error`, as planned. `watch_footage` returned no error, and `source/` held no new download afterwards, though the check Film's `trailer` link was usable at the time.
- **Not shown live:** that Run predates `footage_read`, so its log doesn't name the file. A test proves the event, with its footage id.
