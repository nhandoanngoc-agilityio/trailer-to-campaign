# T31: Apply Claude Code's best practices to this repo's setup

[#84](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/84) · PR [#85](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/85) · ready to merge

Brings the repo's Claude Code setup in line with the best-practices guide (code.claude.com/docs/en/best-practices). A `Stop` hook now enforces lint before Claude finishes. The ticket loop becomes a skill, and the rules that matter in only one folder load only there. `CLAUDE.md` goes from 91 lines to 53 and loses nothing.

## Spec

What the ticket asked for, and what Analyze settled.

- **Done when:**
  1. A `Stop` hook runs `ruff check` and `ruff format --check` on the `.py` files that changed in the working tree (tracked changes and untracked files). It exits 2, with ruff's output on stderr, when either fails, and 0 when they pass or no `.py` file changed. Tests cover both sides.
     _Check:_ `tests/test_hooks.py` cases on a temporary repo: a bad file exits 2 and its stderr names the file, a clean file exits 0, no change exits 0, an untracked bad file exits 2, a deleted file exits 0.
  2. The Stop hook has a time limit, never changes a file, uses only the standard library and runs on Python 3.9, tested like the other hooks. A test pins what it does when ruff is missing or times out.
     _Check:_ the tests run under `hook_python()` (3.9). The file's bytes are unchanged after a failing run. Cases cover a missing ruff and a stubbed ruff that sleeps past the limit.
  3. The ticket loop moves out of `CLAUDE.md` into a skill Claude loads on its own when it works a ticket. `CLAUDE.md` keeps one pointer to it, the 🧑 gates, and every "Never do" line. `ship-ticket`, `review-checklist`, `docs/workflow.md` and `prompt_changed.py` point to the new place.
     _Check:_ a test that every "Never do" line on `main` is still in `CLAUDE.md`, plus a test that no file still points at the loop's old place.
  4. The Layout section keeps only what Claude can't find by reading the repo.
     _Check:_ review the diff. Every removed line is listed in this record with where it went or why it was dropped.
  5. `.claude/rules/` holds path-scoped rules for footage, prompts and the Film Budget.
     _Check:_ a test that every rule file has `paths:` frontmatter and each pattern matches at least one tracked file.
  6. `.gitignore` ignores `CLAUDE.local.md`, and `format_on_edit.py` uses the project's own ruff.
     _Check:_ the line is in the repo's `.gitignore`. A hook test shows `format_on_edit.py` calls the project's ruff and never `uvx`.
  7. `.claude/agents/reviewer.md` is read-only (`tools: Read, Grep, Glob`).
     _Check:_ a test that parses its frontmatter, with no Edit, Write or Bash.
  8. `CLAUDE.md` is shorter and loses nothing.
     _Check:_ `wc -l` before and after, plus the line-by-line table under **Plan**.
- **Decisions:**
  - Lint only, not the tests, in the Stop hook: the full suite takes about 92s (measured on `main`, 1624 tests), too slow for every time Claude finishes a turn. Tests stay a step in Verify, and CI enforces them.
  - Only the changed files are linted, not the whole repo, so a stray file elsewhere can't hold a session. CI still lints everything.
  - When ruff is missing or times out, the Stop hook lets the turn end and says "lint not checked" on stderr (the human, in Plan). A lint gate that blocked on a broken setup would trap every turn of that session, and CI still lints everything.
  - No `.worktreeinclude` for `.env` (the human, in Plan). `ship-ticket` deliberately keeps the key out of worktree sessions and hands paid runs to the human, and `git worktree add` ignores the file anyway. Issue #84 was edited to match.
  - Branch protection on `main` is out of scope: it's a GitHub setting, not repo content, and the human decides it. The audit found none; the API answered "Branch not protected".
  - `review-checklist` needed no change: its "restate `CLAUDE.md`" line still holds.

## Tests

- `tests/test_hooks.py`, the cases for `lint_on_stop.py` and `format_on_edit.py`.
  - Blocks on a bad tracked file, a bad untracked file, a bad file seen from a subfolder, and a file name git would quote.
  - Passes on a clean change, no change, only Markdown, and a deleted file.
  - Never changes a file, and runs both ruff commands with `--force-exclude`.
  - Missing ruff, a timeout, bad input, no git repo, and git unable to tell the project each give exit 0 with "lint not checked".
  - It blocks once, then ends the turn with a `systemMessage` naming the files; every "lint not checked" note is a `systemMessage` too. It leaves another repo alone and still lints a worktree of the project.
  - Both hooks' time limits cover their worst case, and `format_on_edit.py` uses this project's ruff, never `uvx` or another repo's.
- `tests/test_claude_setup.py`, 37 cases: the 6 "Never do" lines, the pointer and gates, the length, the skill's frontmatter and 7 steps, no stale pointers, every rule scoped with each glob matching a tracked file, named paths existing, the prompt-file rule loading everywhere, a rule for the Spoiler List code, the reviewer read-only, and `CLAUDE.local.md` ignored.
- After review: full suite `1689 passed, 1 deselected`. Hook tests on Python 3.9.6, the macOS one: `619 passed`.
