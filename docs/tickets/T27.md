# T27: The Bash guardrail reads nested commands

[#70](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/70) · PR [#81](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/81) · draft

A forbidden command nested in other shell syntax now exits 2: inside `$(...)` or backticks, behind a shell keyword, in `eval`, or under a clustered `-c`. A real heredoc body stays text, and normal commands such as `"$py" --version` stay allowed.

## Spec

T24 found these during review and left them out: each passes on `main`'s hook too. The hook is a tripwire for accidents, not a sandbox, so this ticket closes the forms an agent could plausibly write by accident and says plainly what stays out of reach.

- **Done when:** each of these exits 2 under `/usr/bin/python3` and CI's Python 3.9, or this record says why it stays open:
  - `echo "$(git reset --hard)"`
  - `echo '<<EOF'` followed by a line holding the command
  - `if true; then git reset --hard; fi`, and the keywords `then`, `do`, `else`, `elif`, `{`, `!`
  - `eval 'git reset --hard'`
  - `bash -lc 'git reset --hard'`
  - `${x:-git} reset --hard`, `$x reset --hard`, `git ${x:-reset} --hard`
- **And:** real commands from recent sessions replay with no new false blocks. A real heredoc body stays text.
- **Decisions:**
  - **Expansions (the human's call):** an expansion as the program or as `git`'s subcommand is refused only when the visible arguments already look forbidden. `$x reset --hard` is read as `git reset --hard` would be. `git $x --hard` is read as `reset`, `push` and `add` would be. `"$py" --version` passes. `$x commit` is refused on `main` only, as `git commit` is. A `$x checkout main` doesn't change the branch later commands are judged on, because `$x` may not be git.
  - **An expansion also reads as a wrapper:** `$SUDO git reset --hard` is judged on what follows it. This goes a step past the issue's examples, at no cost to any replayed command.
  - **rm through an expansion only with an option first:** `$x -rf build` is refused, and `"$pip" install -r a -f b` isn't. `$GREP -r -f patterns .` would be refused, a false block we accept.
  - **No total deadline across `git` calls (the human's call):** several slow calls adding up past the hook's 10 s timeout still pass. The hook is a tripwire for accidents, not a sandbox, and slowing `git` on purpose isn't an accident. Each call still has its 3 s limit, and a timeout blocks.
  - **Text that isn't JSON still exits 0 (the human's call):** as T24 recorded.
  - **`$(...)` is read, and what can't be followed is refused:** T24's lesson was not to teach a guard a language it only needs to refuse. Here the ticket needs what's inside `$(...)`, so the scanner follows quotes and parentheses to find its end, and refuses the rest. It holds no new grammar beyond that: a `case` inside `$(...)`, whose `)` would look like the end, is refused rather than parsed.
  - **Heredocs are read by the scanner, not a pass before it:** that is what makes quotes and comments unable to fake one, and it also means any delimiter works (`<<\EOF`, `<<END-OF-TEXT`, `<<'---'`). The delimiter must now match exactly, as in a shell, so an indented `EOF` closes only `<<-`.
  - **A body isn't always text:** with an unquoted delimiter, a shell runs the body's `$(...)` and backticks, which bash, zsh and sh all confirmed. So those are judged, and everything else in the body stays text. The issue didn't name this, but it's the same gap as `echo "$(git reset --hard)"`. With a quoted delimiter the whole body stays text.
  - **Too deep now blocks:** past the nesting limit the hook used to return "no violation". With `$(...)` and `eval` this limit became easy to reach, so it now blocks, and the limit went from 3 to 5.
- **Out of reach, on purpose.** These still exit 0, on `main` too:
  - **An expansion that hides the forbidden part:** `git reset "$mode"`, `git $(echo reset --hard)`, `$x`, `$x --hard`, `eval "$x"`, `bash -c "$x"`.
  - **`$SHELL -c 'git reset --hard'`:** reading `$x -c` as a shell would parse `"$py" -c`'s code as shell.
  - **A shell fed some other way:** `bash <<'EOF'` with the command in its body, `echo 'git reset --hard' | bash`, `source reset.sh`.
  - **Programs that run a command later or for you:** `trap '...' EXIT`, `find . -exec git reset --hard \;`, `function f { git reset --hard; }; f`.
  - **`sudo -u me git reset --hard`:** the wrapper's option value reads as the program. This is older than T27.
- **Refused though harmless, on purpose.** These exit 2, because the hook can't follow them:
  - `echo $[1<<2]` or `let x=1<<2` with more lines after it, because `<<` there reads as a heredoc that never closes.
  - `cat <<EOF` with no closing line.
  - `echo "$(cat <<EOF` closed by `EOF)"`, which bash accepts and zsh rejects. It blocked on `main` too.
  - `echo "$(case x in a) echo hi;; esac)"`.
  - `echo "$(echo `date`)"`, unquoted backticks inside `$(...)`, as they already were outside it.
