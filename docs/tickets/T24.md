# T24: The guardrail hooks work on the machine's python3

[#68](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/68) · PR [#69](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/69) · merged

The Bash guardrail hook blocks again. It had been crashing on the Mac's `python3` since 2026-10-30, and a crash let every command through. Now it runs on Python 3.9, and a crash blocks the command.

## Spec

`.claude/settings.json` runs the hooks with `python3`, which is `/usr/bin/python3`, 3.9.6, on this Mac. `block_forbidden.py` called `zip(..., strict=True)`, which needs 3.10, so every Bash command raised `TypeError` and exited 1. Only exit 2 blocks. The tests used the project's Python, so they stayed green.

- **Done when:**
  - Under `/usr/bin/python3` (3.9.6), `git push --force origin main` and `git push origin main` exit 2, and `git status` exits 0.
  - `tests/test_hooks.py` runs every hook with the `python3` the settings would find, not the project's virtualenv, and goes red on `main`'s code.
  - CI runs the hook tests on Python 3.9 as well, so a runner with a newer `python3` can't hide this.
  - If `block_forbidden.py` crashes while judging a command, it exits 2 and says the command wasn't checked. Input that isn't JSON still exits 0.
  - Ruff judges `.claude/hooks/` as Python 3.9, so it can't ask for 3.10-only code there again.
- **Decisions:**
  - **Keep `python3` in the settings:** the hooks stay on the standard library, so they run before `uv sync` and in any clone. They now promise 3.9, the oldest `python3` a Mac ships.
  - **A failed hook blocks every Bash command until a person fixes it:** that's loud, but silent is what hid this for five days. The block tells Claude to stop and ask, not to edit the guard. `|| exit 2` in the settings covers what the hook's own code can't: no `python3`, a Python older than 3.9, or a syntax error.
  - **A payload with no command blocks:** this hook only sees Bash calls, so that means Claude Code's payload changed, and passing it would be another silent outage.
  - **Text that isn't JSON still exits 0, as the Done-when says:** the human can change this. Claude Code has always sent JSON, so it isn't reached today. Bytes that aren't text never get that far: they crash the read, and `|| exit 2` blocks them.
  - **A slow `git` can still pass a command, in one case:** a `git` call over 3 s now blocks, because the branch is unknown. But Claude Code treats a hook that outlasts its 10 s timeout as a non-blocking error, and `|| exit 2` dies with it, so several slow calls adding up past 10 s would pass. The review suggested a total deadline, which isn't built.
  - **The tokenizer is now our own, about 50 lines:** `shlex` can't read `"\""` and joins `)>`, and each patch around it opened a new gap. A small scanner following the shell's quoting rules replaced it, with no dependency. What it can't follow blocks: a quote left open, unquoted backticks, `>!`, a `$'...'` escape, a `${...}` holding more than plain text. Replaying all 580 distinct Bash commands in this project's session logs gave no such block.
  - **Refuse rather than parse:** the first scanner tried to read backticks and nested `${...}`, and each round of review found new gaps in that, some of them regressions against `main`. Refusing them closed the whole class, and costs nothing the project's real commands use.
  - **Known gaps, not fixed here:** `echo "$(git reset --hard)"`, `echo '<<EOF'` then a line holding the command, `if true; then git reset --hard; fi`, `eval 'git reset --hard'` and `bash -lc 'git reset --hard'` all pass the guard. Each passes on `main`'s hook too, on a Python where it runs, so none comes from this PR. The hook has always been a tripwire for accidents, not a sandbox. This ticket stops at putting it back in force, and whether to close these is the human's call.
  - **Not fixed here:** Ruff can't reject 3.10-only calls written by hand, such as `zip(strict=True)`. The Python 3.9 tests are what catch those.

## Tests

On `main`'s code, 93 of the first 101 hook tests failed on this Mac's `python3`. The reviews added 66 more cases, and those that exposed a gap failed before their fixes. All 167 pass now, on this Mac's 3.9.6 and on CI's 3.9. Ruff's B905 is the likely way the 3.10 call got in: it asks for `strict=` when the target is 3.10 or newer, and the project's target is 3.11. The Ruff test goes red without the per-file target.

## Evidence
