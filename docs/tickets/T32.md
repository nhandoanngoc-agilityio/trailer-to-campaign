# T32: `t2c --version` prints the package version

[#86](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/86) · PR [#<pr>](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/<pr>) · in build

`t2c --version` prints `trailer-to-campaign <version>` and exits 0. The version comes from the installed package metadata, so it follows `pyproject.toml` with no second copy to keep in step.

## Spec

What the ticket asked for, and what Analyze settled.

- **Done when:**
  1. Running `t2c --version` prints `trailer-to-campaign <version>` and exits 0.
  2. The version comes from the installed package metadata, not a hard-coded string, so it follows `pyproject.toml` (today `0.1.0`).
  3. `t2c --help` lists the flag.
  4. A test covers the output and the exit code.
- **Decisions:**
  - The issue's bullets are the Done-when list, and the ticket has no blockers.
  - Long `--version` only. `-V` is free but not asked for, and it sits next to `-v` (verbose).
  - With no package metadata (run from source, not installed), it prints `trailer-to-campaign unknown` and exits 0, so the rest of the CLI keeps working and no version is invented.
  - Tests run both in process and through the installed `t2c` command, and check against the metadata and `pyproject.toml`, never a literal `0.1.0`.
  - Output goes to stdout, as argparse does.
  - One usage line each in the README and the `cli.py` docstring.
  - Top level only: `t2c run --version` stays a usage error.
  - No `__version__` attribute; `pyproject.toml` and `__init__.py` are untouched.

## Plan

The tests written first, the files changed, and anything that changed from the plan during Build.

- **Tests first** (red: 6 failed): six cases in `tests/test_cli.py`.
- **`src/trailer_to_campaign/cli.py`**: `DISTRIBUTION`, `package_version()` (standard-library `importlib.metadata`, falling back to `"unknown"` on `PackageNotFoundError`), and an argparse `version` action right after `-v/--verbose`. argparse prints and exits while parsing, before the subcommand check and before `load_settings`, so the flag needs no subcommand, API key or valid settings. The module docstring gains `t2c --version`.
- **`README.md`**: `uv run t2c --version` in the usage block.

Changed during Build: nothing.

## Tests

- `test_version_prints_the_package_version`: exit 0, stdout exactly `trailer-to-campaign <metadata version>\n`.
- `test_version_matches_pyproject`: the printed version is `[project].version` read with `tomllib`.
- `test_version_needs_no_settings`: a bad `FILM_BUDGET_USD` doesn't stop it. The other side, a subcommand with a bad env still failing, is the existing `test_bad_budget_in_environment_is_a_usage_error`, which still passes.
- `test_help_lists_version`: `--help` names `--version`.
- `test_t2c_version_through_the_installed_command`: the real `t2c` entry point prints the same.
- `test_version_without_metadata`: with the lookup raising `PackageNotFoundError`, `package_version()` is `"unknown"` and the parser still builds.
