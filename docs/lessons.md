# Lessons

One or two lines per ticket: what it taught about building agents for real. Newest at the bottom. These feed the "what we learned" part of the company talk.

| Ticket | Lesson |
|---|---|
| Setup | Writing the glossary and ADRs before any code made every later decision faster: most debates were already settled in writing. |
| Setup | Instructions guide an agent; hooks enforce. The rules that matter most (PRs only, no secrets, an Answer Key nobody can edit to pass) became tested hooks and settings, not just lines in CLAUDE.md. |
| Setup | CI for agents can fail silently. `/install-github-app` overwrote the tuned review workflow with the stock one, and the review action skips (yet shows green) whenever a PR's workflow file differs from `main`'s. Read the run log, not the check mark. |
| T1 | A hard stop is only as hard as what it's told. Two reviews found the edges of the Film Budget meter (a token estimate just under a price tier, an error after the call was billed, a failed log write), and each became a stated contract with a test, not just a patch. |
| T2 | Real footage found what synthetic clips couldn't: Whisper invents dialogue over music. A guard that silently drops data trades one failure for another; setting the doubtful lines aside, marked never to quote, kept both the public and the material safe. |
| T3 | A strict loader is only strict where the data is present. The worst bug in T3 was an absence: a forgotten Spoiler List read as "no spoilers", so the Checker would pass everything. Make the empty case explicit (`spoilers = []`) and refuse the missing one. |
| T4 | Check what an agent says against what it was shown, in code. On its first real run the Watcher cited frames from outside its own Key Moment; a deterministic grounding check sent the problems back and it fixed them on the next try, for cents. A prompt can ask for grounding, but only a check can prove it. |
| T5 | The cheapest guardrail is a citation. Asking the Copywriter to list every claim with its source turned "every fact traces back" from a judgment into a check: code verified 32 citations and both quotes, and the human review became a table to read, not a hunt through prose. |
| T6 | A retry loop is a leak waiting to happen. To fix a spoiler the Copywriter needs to know what's wrong, but telling it why would put the Spoiler List in its context. Sending back only its own offending words, in a fixed sentence, was enough: the real Checker caught both a planted Trap and a real slip, and each was fixed in one retry without the writer ever seeing the list. |
| T7 | A fake that is kinder than the real thing hides bugs. 491 tests passed with fake clients that worked from any event loop; the real async client is bound to the loop it first ran in, so the first person to run the pipeline hit "Connection error" right after approving the Key Moments. The fix shipped with a fake as strict as the real client, and the bug was reproduced for free (count_tokens) before any fix. |
| T8 | An eval measures what you plant, and sometimes what you didn't. Planted Drafts made "caught 9 of 10" deterministic, and Clean Drafts kept a reject-everything Checker from scoring 100%. Its first run also found two surprises no test planned: the Checker catches a swapped cast only for films it already knows (a model's memory, not our data), and the Copywriter wrote control characters that every check passed. |
| T9 | When an integration stays silent, look at what the platform actually sends before touching code. The first Slack run did nothing; a 40-line listener showed Slack was delivering plain channel messages and never `app_mention`, because the app had been set up by hand with the wrong subscription. The code was right; the fix was the app's manifest, which also took away access it never needed. |
| T10 | A quality number people mark themselves needs a measured twin. In the live Slack run every edit was marked Light, so the Approval Rate read 14/15, but the measured change said those "light" edits rewrote 61–85% of the words. Next to each other, the two tell the truth that neither tells alone. And re-checking a person's edit earned its place: the Checker flagged one "Light" rewrite as hinting at the ending. |
| T11 | A ready-made agent harness is mostly something to take away from. On the Agent SDK the Watcher matched v0 on the Eval Set for 7% more, but most of the work was turning things off (built-in tools, settings files, retries, background calls) and finding where control went: a tool's exception never reaches your code, so stopping the Run took a hook. A budget margin must also be checked against real numbers: the first one held back $1.92 of a $2.00 Film Budget. |
| T14 | A guard that parses commands is only as good as its parser. The first version passed 30 hand-picked cases, but a reviewer running real commands found that a newline joined two commands into one, which skipped every check in the hook, the old force-push check included. The layer that sees the result catches what parsing cannot: the commit-time check refuses an Answer Key change however it was written, and the shell hook is the early warning. |
| T16 | Check what you publish at the character level, not only the word level. Every check read the Copywriter's posts as words and passed `\ff\ff` (an emoji escaped by hand, which JSON read as form feeds), and so did the model Checker. A few lines in tracing now refuse it, and because a marketer's edit is re-checked by the same trace, people get the same check for free. |
| T17 | A timeout isn't a deadline. The SDK already had one, but it was per read, so a call that kept its connection open hung for 25 minutes. The limit that holds is one around the whole call, sitting inside the meter so a call that's cut off is still charged. The first value, 300 s, came from our own logs (37 s at most) and would have cut off replies the SDK itself expects to take 450 s: size a limit from what the system may legitimately do, not only from what you've seen. |
| T18 | An error message is a prompt too, and a log that drops what was refused can't explain it. Rewording a rejection to cover rewrites ("all the posts asked for") may be why retries sent only part of the set, but the Run Log kept the problems and not the posts, so the cause stayed a guess. An eval also proves only the paths it reaches: tracing refused no submission in any Eval Set run, so the tests, not the eval, prove this fix. |
| T19 | Going parallel can turn a failure into silence. Every test passed, yet a stray cancellation dropped every Film and the run exited 0 with "$0.00 over 0 Films": a task group treats a cancel as no error, so an eval gate must check that each expected result exists, not that nothing raised. And a probe has to do the real work: "a 2-second tool stalls the loop 0.05 s" measured a sleep, which releases Python's lock, so the number proved little until five real Whisper runs gave 3 s at worst. |
| T20 | Read a spec through its use. The ticket said the Baseline should match "the current" hash, which is exactly what can never match on the prompt PRs it exists for, so it asks for `main`'s hash instead. And a saved number needs a test of whether it can stand in: a run cut short by the API's credit limit read "6 of 10" and would have looked like a real result, so only a whole, clean run counts. |
| T15 | When an eval already scores 100%, ask what it can't see. The Eval Set caught every wrong name partly because the model knows those films, so a made-up Film was the only way to see the gap, and it wasn't the one predicted: with no cast list the Checker didn't miss wrong names, it rejected a correct credit too. Without the data it needed, a guard told to reject when in doubt turned its doubt into false alarms. |
| T21 | When a fix can't be seen working, build the moment instead of waiting for it. T18 merged on tests because the eval rarely reaches a retry. Its Run Log field made it possible to put the real model at the exact moment of two real retries, for cents, and six replays showed what no run had: the bad retries are garbled output, possibly at an emoji, not a misread message. And it pays to design for a failure you can't explain: keeping the good posts works whatever the cause turns out to be. |
| T22 | A human override is data, so record it. Letting a person approve over a guard is right, but the metric then hides it: a live Run read 100% Approval with a post credited to Tom Hanks among them. It took a rehearsal with people to find, because every test checked what was allowed, and none asked what the record would say afterwards. |
| T23 | Check what a link actually points at, not only that it works. A 90-second film published in full sat behind the same kind of link as its 40-second trailer, and only the download check showed the difference: a link that the tool can fetch would have fed every spoiler to the Watcher. And a dependency that fails on and off is the one to design out: YouTube refused this machine and then stopped within the hour, so a passing check that morning would have promised nothing about trial day. |
| T12 | A report can state what it never saw. `t2c result` printed "timed by that marketer's stopwatch" whatever had happened, and only comparing the Run Log's clock with the time the page was written showed the old way had been done hours earlier, from memory. Numbers from a log are hard to bend. The human half of a measurement needs its own record, made at the moment, or the report should ask rather than assume. |
| T13 | A flag isn't a catch until you've read why. In the demo's live Run, a spoken line from the script was pasted into a post by mistake, and the thread showed the same "flagged" it would for the planted spoiler. Only the Run Log showed the Checker had objected to a stray note. The Checker was right, but anyone watching would have seen the wrong proof. A demo's script is a user interface: put what to say and what to paste side by side and one will end up in the other. |
| T24 | A guard has to be tested where it runs. The hook was fine on the project's Python, which is what its tests used, and crashed on the Mac's `python3`, which is what actually ran it. The crash exited 1, not 2, so for five days it blocked nothing and nobody noticed. Green tests proved the code, not the guard: decide what a guard does when it breaks, and make that failure loud. And don't teach a guard a language it needs only to refuse: each shell feature the scanner learned to parse opened new gaps, and refusing what it couldn't read closed them at no cost to any real command. |
| T25 | A checklist is a set of claims, so check it too. Writing one from the project's own bugs was quick, but its first run showed a check that contradicted `CLAUDE.md`, and a look at the source showed an ADR cited for something it never said. Each check that names its source can be read against that source, and a small test keeps the names real. |
| T26 | Try the platform before designing around it. A plan that read "run it under `launchd`" looked done, and a fake `launchctl` would have passed every test, but a 10-line throwaway job showed macOS refusing it access to the repo at all. And moving somewhere new carries a guardrail's data along: the service's own copy of a Film means a changed Spoiler List does nothing until it's copied again. |
| T27 | Check a guard's reading of a language against the language. A heredoc body had always been called text, but a five-second run in three real shells showed that a body with an unquoted delimiter runs its `$(...)`. And a replay only proves the commands you happened to run: no replayed command was newly blocked, while review found `"$py" -m pytest -rf` and `"$FFMPEG" -r 30 -f mp4` refused as `rm -rf`. "Looks forbidden" needs examples from both sides, written down, and even then a text guard guessing at `$x` keeps a few false blocks. |
| T28 | A false claim rarely sits in one sentence. The ticket named the stopwatch line, but a heading, "timed the same way", "Both started" and "a check on the stopwatch" all leaned on it, so fixing that line alone would have left the page claiming it in other words. Test what a report must not say across the whole page. And check why a refusal test is failing: argparse refused the flag before it existed, so the test passed for the wrong reason until it asked for the real one. |
| T29 | A rule against dependencies has a price, so check what it's costing. To avoid declaring a YAML parser already installed, the test got a hand-written one. It claimed to fail safe, review found shapes that passed anyway, and the fix for those then refused an ordinary workflow with JSON in a step. The human dropped the rule, and the 432-line test file became 303 with no new package installed. And a limit's outcome may not carry the name you wrote down for it: this PR's own CI hit its limit on a slow package install, and the job the ticket said would fail ended `cancelled`, which `gh pr checks --watch` listed as `fail` and still exited 0. Check what your tools report at a limit, not only that the limit is set. |
| T31 | A line in `CLAUDE.md` is a request; a hook is a check. The new `Stop` hook caught a line-length error in its own file the first time lint ran, which a written "lint before you finish" depends on Claude remembering to catch. A guard has edge cases of its own: the first version skipped a bad `café plan.py`, because git quotes such names unless asked for `-z`. And shortening `CLAUDE.md` was safe only because a table accounted for every removed line and a test pinned the ones that must stay. |
