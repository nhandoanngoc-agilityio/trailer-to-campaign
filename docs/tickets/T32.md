# T32: `t2c --version` prints the package version

[#86](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/86) · PR [#89](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/89) · Done

`t2c --version` prints `trailer-to-campaign <version>` from the installed package metadata, so anyone can tell which release of the tool they are running.

## Spec

What the ticket asked for, and what Analyze settled.

- **Done when:** `t2c --version` prints exactly `trailer-to-campaign <version>` and exits 0. The version comes from installed package metadata, not a hard-coded string. `t2c --help` lists the flag. A test covers the output and the exit code.
- **Decisions:**
  - A. No short `-V`: the ticket asks only for `--version`, and `-V` is cheap to add later.
  - B. Metadata missing: print `trailer-to-campaign unknown` and exit 0. Failing inside `build_parser()` would break every subcommand from an uninstalled source tree.
  - C. stdout, which is what the argparse `version` action uses on 3.11+.
  - D. Settings are ignored: the flag exits during parsing, before `configure_logging` and `load_settings`, so a bad `FILM_BUDGET_USD` can't affect it.
  - E. Top-level only: `t2c slack --version` is not supported.
  - F. Tests run both in-process (exact text, metadata, `pyproject.toml`) and as a subprocess on the installed `t2c`.
  - G. No docs beyond one usage line in the `cli.py` docstring.
  - H. The issue has no **Blocked by** line, and the ticket depends on no other ticket's code.
  - Not done on purpose: no `__version__` in `__init__.py`, because nothing asks for it. No change to `pyproject.toml`, `README.md`, `docs/deploy.md` or `deploy/t2c-service`. Using the flag to check which release the service runs could be a follow-up ticket. No change to how releases are tagged or versioned. No new dependency: the helper uses only `importlib.metadata`.

## Tests

Six new tests in `tests/test_cli.py`:

- `test_version_prints_the_package_name_and_version`: exact stdout line from `importlib.metadata`, empty stderr, exit 0.
- `test_version_matches_pyproject`: the line carries `[project].version` from `pyproject.toml`, so the number isn't hard-coded.
- `test_version_needs_no_settings`: a bad `FILM_BUDGET_USD` doesn't affect `--version`, and the same env still makes `dummy-run` exit 2.
- `test_version_without_package_metadata_says_unknown`: with `PackageNotFoundError`, the parser still builds and prints `trailer-to-campaign unknown`, exit 0.
- `test_the_help_lists_the_version_flag`: `--version` appears in `t2c --help`, exit 0.
- `test_t2c_version_runs_as_an_installed_command`: the installed `t2c --version` exits 0 with the same line.
