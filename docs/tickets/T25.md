# T25: A review checklist for this repo

[#71](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/issues/71) · PR [#72](https://github.com/nhandoanngoc-agilityio/trailer-to-campaign/pull/72) · merged

The `review-checklist` skill: the checks `/code-review` and `/security-review` can't know, from this project's rules and the bugs it has already shipped.

## Spec

- **Done when:**
  - `.claude/skills/review-checklist/SKILL.md` exists, and every check traces to `CLAUDE.md`, an ADR, `.claude/claude-security-guidance.md` or a line in `docs/lessons.md`.
  - A test fails if the skill names a repo path that doesn't exist, so it can't go stale silently.
  - It reports pass, fail or n/a for every check, with file:line for a failure, and ends in a verdict.
  - It has run on a real PR, with its result in the ticket record.
  - `CLAUDE.md`'s Review step and Layout name it.
- **Decisions:**
  - **Model-invoked:** it keeps a description, so Claude reaches it when reviewing as well as when asked. That costs one always-loaded line.
  - **Points at the security guidance, and doesn't copy it:** `.claude/claude-security-guidance.md` stays the one source for those rules.
  - **Not every check names a source:** those that restate `CLAUDE.md`, `CONTEXT.md` or `README.md` don't repeat where they came from, and the skill says so.
  - **Terminal Approval is a known non-issue:** `CLAUDE.md` and the security guidance say Approval takes a Slack action, but `t2c run` takes it from keystrokes, as the README documents. The checklist treats that as the single-user path. The human may want those two lines to say so.
